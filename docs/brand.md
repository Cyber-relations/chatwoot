# トイバコ ブランド仕様

方向性: **まじめな遊び心**。業務ツールとしての端正さを土台に、遊びはロゴのコーラル一点とフォーカスリングにだけ出す。

## カラー

| 役割 | 色 | 用途 |
|---|---|---|
| プライマリ | `#1F3A5F` ディープネイビー | 箱、見出し、主ボタン |
| プライマリ深 | `#163049` | ボタンhover、箱の影 |

主ロゴは確定した **C改（開いた箱＋緑の3点吹き出し／ピンクのカメラ／封筒）**。原画は `brand/originals/toybaco-logo-c4-dots-in-green.png`。画面用は `overlay/app/public/brand-assets/` に置く。旧ロゴ検討時の箱のみのA案は不採用。C改は商標セーフ（各社ロゴ・固有図形なし）。旧比較ページは `brand/review.html`。資産一覧は `brand/README.md`。

## アプリアイコン／ファビコン／横組みロゴ

2026-09-14 owner 決定：背景案A「アイボリー」を採用し、LP・アプリ全体のトイバコアイコンを背景付きへ統一する。**C4原画の形と色は維持**し、`#FAF7F2` の角丸地（半径23%）と薄い `#E9E1D6` の境界線を使う。マーク画像は一辺の88%に配置する。簡略化、文字の追加、箱のネイビー変更はしない。

共通アイコンは `toybaco-app-icon-ivory.png`（LPは同名WebPも使用）。横組みロゴも左のマークをアイコンへ交換し、既存ワードマークを維持する。LPの動画・ヘッダー・フッター・構造化データ・共有画像、Chatwootのサイドバー・ログイン・初期設定・管理画面、Postizのロゴ・読み込み表示・OAuth、faviconも同じ資産を使う。

16px faviconはマーク画像を96%へ拡大し、未読通知用は従来の右上コーラルドットを維持する。apple／android／msと外部サービス用1024px PNGは全面アイボリー（1024px版はRGB、不透明）とし、OSが角丸を付ける。角丸PNGの透過は四隅の外側だけで、アイコン内にはアイボリーが入る。

生成元は `brand/originals/toybaco-mark-c4-transparent.png` と横組み原画2点に固定する。`python3 brand/tools/generate-icons.py --write` でLP・アプリの52資産を一括生成、`--check` で一致確認する。旧 `toybaco-mark-c4.png`／WebP／SVG参照先にも背景付き画像を残し、既存インストール設定からの参照を保つ。新規参照は共通アイコン名を使う。共有画像は `site/assets/og-src.html` を1200×630で描画して `og.png` を更新する。

## UI トークン（overlay/app/public/toybaco-brand.css）

Chatwoot v4 の `--blue-1..12` をライト／ダーク両方でネイビースケールに再定義し、リテラル埋め込みの `n-brand`／`woot-500` 系クラスは全バリアント（checked/hover/before 等）を列挙して上書きする。`dark` クラスはログイン後は body・未ログインページは html に付くので `.dark` セレクタで受ける。ライトのメイン面は `--surface-1/2` をわずかに暖色化。ウィジェットの色は inbox の `widget_color`（DB 設定）で、新規作成フォームの既定は `#1F3A5F`。既存の顧客設定色は維持する。ヘルプセンターの新規ポータルも同じ初期色を使う。

ログイン後の受信箱シェル（ナビ選択・会話タブ・選択行・吹き出し・解決ボタン・作曲欄）は、公開 LP（`site/index.html` の `.pack-mock` / `.app`）のクロム（幅・半径・選択）に overlay CSS で寄せる。`--toybaco-navy-deep` は本表の `#163049` を正とし、LP ページ `:root` の `#16273E` は持ち込まない（第三の値も作らない）。投稿入口・OIDC・ログイン画面は対象外。

埋め込み投稿カレンダーの視覚（タイトル「投稿カレンダー」、主ボタン navy 半径 8px、カード半径 9–11px、ペーパー面 `#FCFBF8`、ステータスピル 承認待ち `#FDF2E3/#B26A00`・公開済み `#E7F6EC/#0B7A35`・予約 `#E8EEF5`+navy）は、公開 LP の `.pack-mock` 投稿面に Postiz テーマ CSS で寄せる。`--toybaco-navy-deep` は本表の `#163049` を正とし、LP ページ `:root` の `#16273E` は持ち込まない。Coral は主ボタンに使わない。Zen Kaku CDN と生産 `#app` の窓飾り（16px 枠・信号機・時計）は付けない。OIDC・チャンネル追加・iframe 入口は対象外。週次カレンダーの IA 書き換えもしない。埋め込みヘッダに「ソースコード」リンクは出さない。

## ソースコードの提供（AGPL）

投稿画面の基盤は AGPL-3.0 の Postiz 改変版である。稼働中バージョンの Corresponding Source は公開リポジトリ [Cyber-relations/postiz](https://github.com/Cyber-relations/postiz) で提供する。顧客向け埋め込みヘッダ（`#/toybaco/posting`）には「ソースコード」リンクを出さない。アプリの「トイバコについて → ライセンス情報」から、問い合わせ対応の `/toybaco/source` と投稿管理の `/api/toybaco/source` に到達できる。各エンドポイントは稼働版に対応するソースを提供する。投稿側の法務案内 `/api/toybaco/about` からのソース提供も維持する。法務・ライセンス情報は通常の機能ナビゲーションと区別し、製品名を偽装しない。LICENSE / NOTICE などの法務ファイルは削除しない。

## 顧客向けの導線

投稿URLを新しいタブで開いた場合も、トイバコ本体の投稿メニューへ戻す。URLの `tb_embed=1` や過去の埋め込みcookieだけで、通常ブラウザの単独画面を許可しない。iframe、認証コールバック、共有プレビューとソース提供はそれぞれの動作を維持する。

プロフィールのヘルプ・更新情報、テンプレートとWebチャット本人確認のガイド、SNS接続制限時の案内は `/toybaco-help.html` に集約する。サポートは `support@toybaco.jp` へつなぐ。上流サービスのリンクをCSSで隠す方式に戻さない。

投稿のグラフ、選択状態、メディア、ダイアログ内に直接記述された旧ブランド色もパッチ時に置換する。ダーク表示では主ボタンを `#2E5580`、グラフ・選択枠を `#8EB2D8` とし、単独表示の旧紫アクセントも同じ配色へ揃える。SNSプレビューに必要な各SNSの色、顧客が指定した色や画像・本文、互換性に必要なSDK識別子は変更しない。ボットの既定画像とロゴ未設定時の画像には承認済みアイコンを使う。
